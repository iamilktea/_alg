
# Power of 2 ($2^n$) 效能比較與實作練習

本專案實作並比較了計算 $2^n$ 的四種不同方法，並以 $n = 100$ 作為測試基準，分析其執行效率、時間複雜度與空間複雜度。

---

## 程式方法說明

1. **方法 1：內建運算子 (`2**n`)**
   - **原理**：直接利用 Python 底層優化的運算子進行計算。
   - **特性**：執行速度最快，由底層 C 語言最佳化處理。

2. **方法 2a：遞迴加法 (`power2n(n-1) + power2n(n-1)`)**
   - **原理**：透過將 $2^n$ 拆解為 $2^{n-1} + 2^{n-1}$ 的遞迴加法。
   - **特性**：**出不來（無法在合理時間內完成）**。因為沒有記憶重複計算的值，產生了大量的重複分支，時間複雜度高達 $O(2^n)$。當 $n=100$ 時，總運算次數高達 $2^{100}$ 次，實際執行會無限期卡死。

3. **方法 2b：遞迴乘法 (`2 * power2n(n-1)`)**
   - **原理**：將問題化為線性遞迴關係。
   - **特性**：執行順暢，時間複雜度為 $O(n)$，遞迴深度為 100 層，在 Python 預設的安全範圍內。

4. **方法 3：遞迴 + 查表快取 (`Memoization`)**
   - **原理**：結合遞迴加法，並使用字典 (`memo`) 記錄已計算過的值。
   - **特性**：雖然初次計算仍需經過線性遞迴，但由於查表機制避免了重複的分支運算，時間複雜度有效降至 $O(n)$。

---

## 效能測試結果 ($n = 100$)

| 方法 | 演算法類型 | 時間複雜度 | 實際耗時 ($n=100$) | 備註 |
| :--- | :--- | :--- | :--- | :--- |
| **方法 1** (`2**n`) | 內建算術 | $O(1)$ / 最佳化 | 極快 ($\approx 0.001$ 毫秒以下) | 效能最佳 |
| **方法 2a** (遞迴加法) | 二元遞迴 | $O(2^n)$ | **無法完成 (無限卡死)** | 數值過大導致嚴重效能爆炸 |
| **方法 2b** (遞迴乘法) | 線性遞迴 | $O(n)$ | 數毫秒內完成 | 表現良好 |
| **方法 3** (遞迴+查表) | 動態規劃/快取 | $O(n)$ | 數毫秒內完成 | 透過快取優化重複調用 |

---

## 結論

- **最快的方法**：**方法 1 (`2**n`)**，建議在實際開發中優先使用語言內建的最佳化運算子。
- **會出不來的方法**：**方法 2a**，這是典型的「指數爆炸」反面教材，未優化的二元遞迴會造成嚴重的資源浪費。
