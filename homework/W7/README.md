
# 第七週習題：動態規劃與組合數計算 $C(n, k)$ 的實作與比較

**排列組合中的組合數 $C(n, k)$（從 $n$ 個元素中取出 $k$ 個元素的可能情況數）**，分別透過"非動態規劃（純遞迴法）"與"動態規劃（Dynamic Programming）"來解決，並深入分析兩者的原理、複雜度與優劣。

---

## 一、 問題定義

組合數 $C(n, k)$（又稱二項式係數）代表從 $n$ 個相異元素中，無順序地選出 $k$ 個元素的方法數。其數學遞迴關係式為：

$$C(n, k) = C(n-1, k-1) + C(n-1, k)$$

基本邊界條件（Base Cases）為：
* 當 $k = 0$ 或 $k = n$ 時，$C(n, k) = 1$。
* 當 $k > n$ 時，$C(n, k) = 0$。

---

## 二、 方法一：非動態規劃（純遞迴法）

### 1. 原理說明
純遞迴法直接根據巴斯卡三角形（Pascal's Triangle）的數學定義進行展開。每當計算 $C(n, k)$ 時，函式會自我呼叫計算 $C(n-1, k-1)$ 與 $C(n-1, k)$，直到遇到邊界條件為止。這種方法完全沒有記憶過去算過的值，導致大量重複計算。

### 2. 程式碼範例
```python
def combination_recursive(n, k):
    # 邊界條件
    if k < 0 or k > n:
        return 0
    if k == 0 or k == n:
        return 1
    
    # 遞迴呼叫
    return combination_recursive(n - 1, k - 1) + combination_recursive(n - 1, k)
```

### 3. 複雜度分析
* **時間複雜度**：$O(2^n)$。由於遞迴樹會呈指數級別展開，許多相同的子問題（例如 $C(n-2, k-1)$）會被重複計算非常多次。當 $n$ 稍大時，程式就會陷入無窮無盡的計算中。
* **空間複雜度**：$O(n)$。空間消耗主要來自於遞迴呼叫時的系統呼叫堆疊（Call Stack）深度，最大深度為 $n$。

---

## 三、 方法二：動態規劃（Dynamic Programming）

### 1. 原理說明
動態規劃透過「由下而上（Bottom-Up）」的方式，建立一個二維表格（DP Table）來儲存每一個子問題 $C(i, j)$ 的解。當我們要計算較大的組合數時，可以直接從表格中查閱已經算好的較小組合數，徹底消除了重複計算的問題。

### 2. 程式碼範例
```python
def combination_dp(n, k):
    if k < 0 or k > n:
        return 0
    if k == 0 or k == n:
        return 1
    
    # 建立大小為 (n+1) x (k+1) 的二維 DP 表格
    dp = [[0] * (k + 1) for _ in range(n + 1)]
    
    for i in range(n + 1):
        for j in range(min(i, k) + 1):
            if j == 0 or j == i:
                dp[i][j] = 1
            else:
                dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j]
                
    return dp[n][k]
```

### 3. 複雜度分析
* **時間複雜度**：$O(n \times k)$。雙層迴圈遍歷了表格中的有效儲存格，運算次數與 $n \times k$ 成正比，速度極快。
* **空間複雜度**：$O(n \times k)$。需要一個二維陣列來儲存狀態。（註：若進一步進行空間優化，僅保留前一行資料，空間複雜度可降至 $O(k)$）。

---

## 四、 兩者綜合比較

| 比較維度 | 非動態規劃（純遞迴） | 動態規劃（DP） |
| :--- | :--- | :--- |
| **核心思想** | 直接展開遞迴定義，無狀態保留 | 紀錄子問題解（Tabulation），避免重複計算 |
| **時間複雜度** | $O(2^n)$（指數成長，極易超時） | $O(n \times k)$（多項式時間，高效穩定） |
| **空間複雜度** | $O(n)$（僅消耗遞迴堆疊） | $O(n \times k)$ 或 $O(k)$（需額外表格空間） |
| **優點** | 程式碼直覺、易於理解數學定義 | 效能極佳，能處理大規模的 $n$ 與 $k$ |
| **缺點** | 效率極差，稍微增加 $n$ 就會導致效能崩潰 | 需要額外的記憶體空間來儲存表格 |
